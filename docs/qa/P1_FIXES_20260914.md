# P1 fixes and verification — 2026-09-14

## Saved draft resume

Fixed the saved-draft listing to keep a selectable, numbered workflow. Selection by number or name opens the existing record, checks ownership, restores template/fields/language/lifecycle and persists that state through ChatService for the next request. Opening does not call generation. A named open request resolves against saved candidates rather than silently using the active draft. Previously active draft state is parked when switching.

New regression coverage includes selection by number/name, no duplicate generation, ownership denial without memory mutation, and ChatService persistence of restored state. Live multi-turn HTTP retest with the deployed build remains pending.

## Natural retry

The current tree already implements case/whitespace/punctuation-insensitive resend recognition in app/intent/classifier.py, plus timeout/retry handling in ChatService. Existing routing, multi-turn and deadline tests pass. No new fuzzy/semantic match was introduced: a changed amount, date or request must not silently replay the old question. Arbitrary paraphrases are not guaranteed to count as retries. The previous QA description of an unimplemented exact-resend fix is stale relative to this code.

## Performance evidence and changes

Existing logs_qa_session6_server.log contains retrieval timings as high as 143730 ms versus LLM call timing up to 45314 ms in chat_pipeline_timing. This does not establish provider contention as the main cause. Local vector and BM25 legs both show large wall times; those include contention/queueing and should not be interpreted as isolated CPU time.

The BM25 upload/update path synchronously rebuilt and persisted the whole index on the event loop. It now runs that work in worker threads, reuses unchanged term-frequency dictionaries, and recomputes global IDF/average length so ranking semantics remain unchanged. Search captures a consistent index/IDs/text/metadata snapshot during rebuilds. No extra embedding model or vector service is required.

Local cosine ranking now constructs result objects only for top candidates. Added separate Mongo scan/scoring, embedding, and BM25 rebuild/persistence timings without logging document text.
